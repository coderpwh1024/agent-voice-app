# 本机 Markdown 记忆

“记忆与对话 → 本机记忆”与个人主页提供入口。兼容后端默认选择本机模式；可以选择下次连接使用服务端 Mem0。现有 Mem0 页及其历史/分页/修改/删除功能保留。

## 存储与操作

- Android：App 的 `noBackupFilesDir/memories/`；iOS：排除系统备份的 Application Support `memories/`，设置系统文件保护。
- 每个服务地址与账号独立目录，正文文件为 `MEMORY.md`。不需要共享存储权限，不自动上传整库。
- 本机支持添加、编辑、按分类/关键词查看、来源证据、版本检查、候选确认及遗忘。
- 使用“复制 Markdown 备份”主动复制完整有效记忆到剪贴板，再粘贴到用户选择的安全位置；“导入 Markdown”粘贴备份并确认替换。备份不包含待整理任务与未确认候选。
- 本期没有自动云备份、跨设备同步或独立应用层加密保险库。卸载/清理 App 或丢失手机可能丢失记忆，剪贴板备份应妥善保管并及时清除。

## 对话与提炼

App 协商 `/voice/capabilities.local_memory.version=1`，创建会话时发送 `memory_mode=local`。每轮服务端请求 `memory.context.request`，App 返回至多 8 条、3000 Unicode 码点的参考；画像优先，其余使用中文双字词/英文词匹配。当前不含手机向量检索。

收到 `input.accepted` 的最终输入才持久创建提炼任务。任务以 `turn_id` 去重，经 `/local-memories/extract` 返回候选后写回本地；纯控制事件、重复接收、中间 ASR 不创建任务。App 重启后在下次连接或记忆页重试继续处理，不要求后台常驻。

自动新增仅适用于低敏候选；修改、删除、清空与其他候选在本机页预览确认。模型主回复不能直接操作文件，也不能代替落盘回执。整理失败保留任务与重试入口，不阻塞语音回复。

关闭“自动整理新记忆”取消待处理任务和候选，保留已保存正文；关闭“回答时使用本机记忆”不再给聊天提供已有记忆。模式切换在重新连接后生效，已建立会话不会中途切换存储源。

切换“回答时使用本机记忆”也会取消旧整理任务与候选，并重置后续普通对话使用的近期上下文，避免旧回答继续带入个人事实。后续新输入仍按“自动整理”开关处理。

## 一致性与隐私

文件采用临时写入、flush、rename；同账户写入串行。编辑器检查条目版本，候选检查修订/遗忘代次。删除、清空、导入和模式变化取消旧任务，迟到结果不写回。一次确认变更会使其他待处理候选失效；冲突时重新整理或手动修改。

遗忘后普通对话不再使用该代次之前的近期聊天作为模型上下文，聊天历史仍可回看。本机遗忘不会删除 Mem0 或聊天记录，它们仍按各自入口管理。

本机保存并不意味着数据不出手机：筛选参考和需要提炼的该条输入会交给服务端/模型，生成的聊天回答仍由服务端保存，外部追踪遵循后端配置。服务端不把上传参考另存到 Mem0，也不将参考原文放进检查点状态或运行配置。

## 开发验证

存储测试在临时目录中注入 `LocalMemoryStore(directory: ...)`，无需访问真实账号文件。协议测试使用本地 HTTP/WebSocket 假服务，页面测试覆盖 320px、200% 文字、深浅色和编辑确认。

后端配置和接口详见相邻仓库的 `docs/local-memory.md`。真机语音、真实模型提炼质量与跨设备恢复需另行验收；当前不存在自动跨设备恢复功能。
