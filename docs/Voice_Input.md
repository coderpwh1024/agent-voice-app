# 语音页的文字与听写输入

语音页提供三种输入方式。业务逻辑、记忆、邮件、视频和执行进度均由后端同一助手处理；客户端负责输入、展示、音频播放、取消和业务确认。

| 入口 | 操作 | 后端会话 | 页面状态 |
| --- | --- | --- | --- |
| 文本框 | 写文字后直接发送，无需先开始语音 | `input_mode=text`，`input.text` | 连接 → 文字就绪 → 思考/执行 → 播报 → 文字就绪 |
| 语音转文字 | 点输入框左侧麦克风，完成后点停止，编辑草稿再发送 | `input_mode=transcription`、`turn_detection=manual`，停止时发送 `input.commit`；收到 `transcript.final` 后关闭 | 听写 → 转换文字 → 可编辑草稿；发送前不运行助手 |
| 语音对话 | 原“现在开始说话”或离线唤醒 | 默认 `input_mode=conversation` | 原唤醒、收音、插话、思考、播报状态 |

纯文字连接使用原生 `playback` 模式，只启动播放器，不请求录音权限、不采集或上传麦克风。首页原有离线唤醒是独立的录音能力，使用文字或听写时会暂停；“现在开始说话”可重新进入双工会话。

听写保留语气词，实时字幕与消息列表分开。已有草稿保留，转写结果追加到文本框；空识别提供重试提示，不产生聊天消息。听写失败、断开、切到后台会清理录音与仅转写会话。结束听写不自动调用助手；用户编辑后按发送才运行。

切换输入方式沿用当前助手、音色和 `thread_id`。纯文字与编辑后的转写文本都使用 `input.text`，保持相同流式文字、TTS、执行进度、记忆确认、审批与视频卡片。播报时仍可发送文字或停止回答，双工插话按钮仅在双工会话有效时展示。连接失败保留草稿，业务失败保留已发送消息，用户可核实后再发送。

后端 `/voice/capabilities.input_modes` 必须声明新模式；旧服务缺省仅支持 `conversation`，不将未知字段静默当成双工收音。新服务的 `session.ready` 与会话详情返回实际 `input_mode`。

## 验证

```sh
flutter analyze
flutter test
```

`test/features/text_dictation_controller_test.dart` 验证无需麦克风的文字输入、手动提交听写、草稿不自动发送、同线程切换、空识别和失败清理。语音页测试覆盖未连接直接发送、听写回填、编辑后发送，以及 320px、200% 字体、键盘和深浅色布局。

`integration_test/text_dictation_test.dart` 使用手机保存的安全登录态与电脑本地后端，默认验证三模式能力、纯文字建联、仅转写合成测试 WAV、历史不新增，以及原生纯播放不采集麦克风。合成素材通过本机 8766 提供并用 USB reverse 映射，来自 `test/fixtures/wake_word/with_command.wav`，不采集用户音频。可选 `LIVE_AGENT_TEST=true` 才实际发送两轮消息并验证模型与 TTS；模型余额/凭据不可用时，应明确记录该范围未通过，不以静音播放或契约测试替代真实模型验收。

USB 交付使用 `scripts/install_usb_debug.sh`，正常入口为 `lib/main.dart`，服务地址为 `http://127.0.0.1:8000`，依赖 `adb reverse tcp:8000 tcp:8000`。覆盖安装保留用户数据，测试后必须恢复正常入口。
