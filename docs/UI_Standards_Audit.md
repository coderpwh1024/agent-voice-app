# UI 规范排查与修正记录

日期：2026-10-23。依据：[AGENTS.md](../AGENTS.md)。

本轮检查共享主题、登录/注册/验证码、个人资料及编辑、连接设置、语音欢迎与消息/偏好/操作区、个人收藏、聊天列表及详情、记忆列表/详情/编辑/变更历史，以及视频创建/作品列表/详情/对话卡片/播放器。以现有暖白、墨黑、低饱和橄榄色和编辑式排版为基础，直接修正偏离规范的细节。

## 已发现并修正

| 范围 | 原有问题 | 修正 |
| --- | --- | --- |
| 视频标题 | 工作室、详情和对话卡片对无标题记录的称呼不同；长标题在详情占用过多首屏 | 统一 `VideoReference.displayTitle` 编号回退；卡片最多两行，详情保留全文，超过 40 个码点时降低字号 |
| 标题/封面说明 | 创建表单未说明后端提取标题、生成成片封面和替换暂存地址的行为 | 按当前运行服务 `/openapi.json` 和后端 schema 更新说明，以任务返回值展示；输入仍为可选，沿用原序列化和幂等逻辑 |
| 封面预览 | 预览封面会校验整张生成表单，未填画面描述时无法单独预览 | 独立校验封面地址；非法地址在该字段旁提示，预览不创建生成任务 |
| 封面缺失与加载 | 对话卡片缺封面时直接移除封面区域；播放器加载阶段出现大块空白 | 共用中性封面占位与主题 Token；视频加载期间保留封面和清楚的加载反馈 |
| 播放交互 | 详情加载时立即初始化视频；原进度条拖动区域小 | 点击播放后才初始化；进度改为有完整操作区与秒数语义的 Slider，保留暂停、缓冲、重试和资源释放 |
| 状态、错误与深色 | 视频状态/语音状态与删除操作存在独立硬编码颜色；部分按钮内加载圈在反色按钮上对比不足 | 常规状态使用共享配色，失败和删除采用主题语义色；错误文字/操作使用匹配的前景色，按钮加载圈适配反色 |
| 个人主页与编辑 | 缺少统一宽屏约束；账户信息横排截断长邮箱，头像操作缺少明确语义且热区偏小；无邮箱也显示邮箱验证标签 | 复用 `EditorialLayout`，信息改为标签/可复制值上下排，头像按钮提供提示和至少 48px 热区；仅有邮箱时显示验证标签 |
| 连接设置 | 表单宽度与头像样式不一致；仅检查 URL 协议，错误通过短暂提示展示 | 限宽 480、复用头像组件，保持弹层按内容收缩；补充主机和内嵌凭据校验，错误就地显示，保留输入 |
| 聊天与记忆布局 | 助手名称与标签挤在横排，日期说明在大字体下争用空间；历史气泡和编辑页边距不统一 | 助手选择上下排，日期说明可换行；历史气泡收紧圆角，记忆编辑采用 24px 主边距 |
| 通用控件与文案 | 部分文字/图标按钮未明确保证 48px 热区；错误圆角、辅助说明换行及静态字体字重不一致 | 在共用主题收敛热区、密度和表单说明/错误行数；统一小圆角，静态宋体使用其实际 400 字重 |
| 语音界面 | 建议看起来可点击但没有操作；降噪/回声状态横排挤压，错误正文只显示三行 | 建议点击后填入草稿，不自动发送或连接；状态可换行，移除冗余嵌套滚动；错误保留全文和原重试/设置/关闭操作 |
| 昵称字段 | 客户端按可见字符簇计数，后端按 Unicode 码点限制，组合字符可能绕过前端 64 字符校验 | 按 `.runes.length` 计数和校验，并在字段旁显示计数与超限提示；保存仍使用已有接口 |
| 登录及文档 | 登录切换动效未读取减少动画设置；文档残留旧粉紫配色和旧封面语义 | 动效响应系统设置；同步 README、视频文档和共享布局规范 |

## 保留并核对的行为

- 标题、封面、生成/转存状态通过现有模型贯通创建响应、列表、详情及结构化实时/历史卡片；没有缺字段时崩溃或自行猜测视频链接的改动。
- `video.task`、`video.list`、`response_metadata.video` 的兼容、排序、真实总量、重复事件更新和取消后的迟到事件隔离沿用已有实现。
- 工作室网格/列表切换保持原数据，不重复请求；小屏/大字体使用单列，4:5/16:9 仅用于封面裁剪。
- 视频播放继续要求 `SUCCEEDED + STORED + 有效 HTTP(S) 持久地址`；图片与视频请求不附带应用 Bearer Token，不展示供应商临时签名地址。
- 原有语音控制器、PCM、VCE1、认证、视频请求幂等及分页实现不因视觉检查被改写；保留用户工作区已有的多视频结果对接改动。
- 记忆仍按游标显示已加载数量，聊天仍按 UTC 日期归档，记忆时间仍按本地时间；删除确认与不确定写入保护保持。

## 验证与证据

自动化执行：

```sh
flutter analyze --no-pub
flutter test --no-pub
```

本轮新增 `test/features/ui_standards_test.dart`，覆盖按钮热区、连接弹层内容高度、无标题/缺封面回退、独立封面预览、播放前不请求视频、原生播放器释放、昵称组合字符上限、设置字段错误，以及 320px/200% 文字下的聊天列表、建议操作和音频状态换行。也检查浅色/深色错误与空态。

可选的错误/空态截图使用 `UI_AUDIT_PREVIEW_DIR`、`UI_AUDIT_PREVIEW_FONT`（本地中文正文字体）和 `UI_AUDIT_ICON_FONT`（本地 MaterialIcons 字体）三个 Dart Define 生成；正常测试不依赖这些机器路径或外部字体。

真机使用现有两个 UI 驱动，复用安全登录态读取实际账户、聊天、记忆和视频。视频检查网格/列表、暂存封面预览、详情点击前无播放器，以及既有影片实际原生播放。语音待机/消息采用受控状态预览，本轮没有创建真实网络语音会话、没有新增视频任务，也没有更新资料或编辑/删除记忆。

截图核对涵盖欢迎/消息、偏好、登录、资料/编辑、收藏、聊天列表/详情、记忆及变更历史、设置、视频网格/大图/创建/详情/播放和浅色/深色。错误/空态截图为共用组件的受控测试场景，不冒充实际后端报错。

证据目录（均在被忽略的 `build/` 内）：

- `build/editorial-ui-verification/`：账户、语音状态、对话与记忆截图及结果。
- `build/video-ui-verification/`：工作室、封面、详情和原生播放截图及结果。
- `build/ui-standards-verification/`：本轮构建、驱动日志、错误/空态截图及最终正常入口包。

测试入口完成后恢复 `lib/main.dart` 正常入口，使用 `scripts/install_usb_debug.sh` 覆盖安装并保留应用数据。USB 包仍通过 `http://127.0.0.1:8000` 和 `adb reverse tcp:8000 tcp:8000` 访问电脑本地服务，不使用模拟器地址。

本轮不包含 iOS 原生录音/播放或真实 ASR/TTS 通话验收；对应交互的原有自动化回归继续执行。

最终结果：静态检查无问题，全部 117 项自动化测试通过；两个 USB UI 驱动均通过。正常入口构建号 46 已覆盖安装并启动，确认 USB 本地服务端口映射存在。最终安装包为 `build/ui-standards-verification/agent-voice-ui-standards-usb.apk`，验证摘要与 SHA-256 位于同目录 `verification.json`。
