# 视频工作室

独立模块位于 `lib/features/videos/`：`data/` 维护请求与契约，`video_studio_page.dart` 维护作品列表，`video_create_page.dart` 维护生成表单，`video_detail_page.dart` 维护查询、轮询和播放器，`video_edit_page.dart` 维护标题与封面编辑，`video_widgets.dart` 维护视觉组件，`video_image_input.dart` 与 `data/video_image.dart` 复用图片选择、校验、上传和预览。复用现有 `AgentApiClient` 的 Bearer 认证和统一响应解析；不持有模型或七牛密钥。

## 入口与设计

首页右上角的影片图标进入视频工作室；“记忆与对话”也提供同一入口。打开工作室时暂停本地唤醒，返回首页后恢复。正在语音通话时禁用入口，避免影片播放与语音采集冲突。

视频工作室采用 Instagram 风格的杂志排版：暖白底色、墨黑文字、细分隔线、少量低饱和橄榄色，作品封面承担主要视觉。入口名称仍为“视频工作室”，页头使用“映像 / STUDIO”字标与小号中文说明，固定标题使用本地打包的宋体，正文和用户影片标题沿用系统无衬线字体。

设计参考：

- [Instagram 官方品牌设计说明](https://www.meta.com/design-at-meta/blog/the-new-instagram-brand-identity/)：克制的界面、更多呼吸空间，让内容成为主角。
- [Kinfolk](https://www.kinfolk.com/)：摄影优先、清晰层级与杂志式留白。
- [摄影档案移动端案例](https://www.behance.net/gallery/201812475/Portfolio-website-for-photographer-Web-Design)：简洁作品网格与细节信息的组织。

首页取消促销式插画大卡，使用字标、编辑式标题和主创作按钮，作品区提供双列 4:5 封面网格及单列 16:9 大图列表切换；切换仅改变布局，不重新请求或丢失分页数据。小屏或大字体自动使用单列。封面比例只影响预览裁剪，不改变原影片比例。空封面与加载失败提供中性占位，失败分页提示放在加载入口附近。

创建页采用统一的分段编辑区与细边输入框，先选择模型，再填写画面、可选素材、作品信息与生成设置；详情以标题和影片为主，创作进程可展开查看。对话视频卡片和独立播放器同步采用同套圆角、配色与字级。主题已提取到 `lib/core/theme/`，视频、语音、个人主页、对话与记忆共用同一套配色和控件。支持深色模式、安全区域及系统大字体。宋体为 SIL OFL 1.1 授权 Noto Serif SC 的静态子集，授权与来源位于 `assets/fonts/`，约 218 KB，不需要联网加载字体。

## 接口

已核对相邻后端仓库 `docs/Video_API.md`、视频 schema、路由、服务与运行中的 `/openapi.json`。整体后端还包括邮箱认证、用户资料、语音会话、聊天调用/流式/历史/归档、长期记忆、邮件技能及 AG-UI；新增模块沿用现有认证和服务地址。

| 操作 | 接口与行为 |
| --- | --- |
| 生成 | `POST /videos`，带 `Idempotency-Key`，解析 HTTP 202 中的统一响应 |
| 列表 | `GET /videos?page=1&page_size=20`，按需传 `status`、`storage_status`、`model` |
| 详情 | `GET /videos/{record_id}`，可从列表进入或按编号查询 |
| 编辑展示信息 | `PATCH /videos/{record_id}`，只提交改变的标题和／或封面 URL |
| 删除作品 | `DELETE /videos/{record_id}`，二次确认后从作品列表移除 |

身份由当前 Bearer 令牌绑定，不向视频接口发送 `user_id`。列表显示后端真实 `total`，按后端页码加载，去除并发变化可能带来的重复 ID。筛选包括全部、已完成（生成成功且已转存）、生成中、排队中、生成失败；其他状态仍可在“全部”与详情查看。分页失败保留已加载作品，刷新失败可重试原刷新。

表单支持两个 HappyHorse 模型、全部九种比例、480P/720P/1080P、3–15 秒、水印与可选随机种子。1.0 模型不会发送 480P。按 Unicode 码点验证最多 5000 字符及最多 2500 个中日韩统一表意文字，种子范围 0–2147483647。

万相 3.0 标准版 `wan3.0-video` 和高速版 `wan3.0-video-prime` 共用上述视频接口、分页、状态、封面与播放器。已核对后端 `docs/Video_API.md`、`src/schema/video.py`、`src/service/video.py`、供应商适配与服务实现，以及本地运行服务的 `/openapi.json`，当前契约一致。

| 万相参数 | 前端行为 |
| --- | --- |
| 画面描述 | 最多 20000 个 Unicode 码点；有有效首帧时可留空 |
| 首帧与尾帧 | 优先从相册选择并上传，使用返回 URL；也可展开填写 HTTP(S) URL，去除首尾空白，最多 2048 码点，拒绝内嵌凭据；提供尾帧必须提供首帧 |
| 时长 | 2–30 秒整数；智能时长发送 `-1`，不伪造最终时长 |
| 比例 | adaptive、21:9、16:9、4:3、1:1、3:4、9:16；默认沿用 16:9 |
| 清晰度 | 480P、720P、1080P |
| 随机种子 | 可选 `-1` 或 0–2147483647，`-1` 表示随机 |
| 生成音轨／智能改写提示词 | 独立开关，初始均开启，仅向万相发送 |

相册图片在上传前校验实际格式、文件大小与尺寸：JPG/JPEG/PNG（无透明通道）/BMP/WEBP，单边 240–8000 像素、宽高比不超过 8:1、单张不超过 20 MiB。地址模式校验 URL 与参数组合，远程媒体内容与可访问性仍由后端及供应商校验。输入图片与 `cover_url` 分开，成片封面仍使用后端从视频提取并持久转存的返回值，不自动把首帧当封面。

切换模型会收敛不兼容的比例、时长和清晰度；从万相切回 HappyHorse 时不发送首尾帧、音轨与改写字段，随机种子 `-1` 清为空值。创建表单整体保持挂载，校验和键盘避让覆盖全部字段。`VideoDraft` 负责共用规则，提交附近显示可见错误；未知结果继续锁定完整参数及原幂等键。作品列表可组合模型与状态筛选，翻页保留模型条件；切换布局不触发接口请求。生成响应、列表、详情、实时 `video.task`／`video.list` 与历史消息均保留模型和首尾帧字段，列表及对话卡片显示真实模型，详情可复制查看素材地址。旧记录缺字段仍正常展示。

同一次提交在重试时使用原幂等键和参数；请求中禁用重复点击和返回。返回未知结果时锁定参数，并允许核对原提交。在当前工作室中重新打开表单仍保留该次待确认提交。此状态只保存在内存；退出工作室或重启 App 后，应先在作品列表核实已提交任务，避免主动新建重复需求。后端返回 `SUBMISSION_UNKNOWN` 时详情明确要求核实，不自动重新生成。

详情页仅在前台每 10 秒查询尚未完成的任务，最多连续自动查询 60 次；切后台暂停，回前台重新核对。查询失败停止自动请求并提供手动刷新。已完成、失败、取消、失效、提交待核实分别展示；生成成功但转存失败保留成功事实并提示后台会重试，不展示虚假的进度百分比。

只有 `status=SUCCEEDED`、`storage_status=STORED` 且七牛 URL 为有效 HTTP(S) 链接时才加载播放器与提供复制链接。阿里云临时签名链接不展示、不复制。播放器使用 Flutter 官方 `video_player`，支持播放、暂停、拖动进度、缓冲和失败重试；离开 App 时暂停，页面销毁时释放资源，不自动开始播放。

后端公开任务包含可空的 `title` 和 `cover_url`，生成响应、列表、详情统一解析。创建页提供可选标题（最多 200 个 Unicode 码点）、折叠的可选暂存封面（相册上传或 HTTP/HTTPS URL，最多 2048 个 Unicode 码点）和独立手动预览；首尾空白会去除，未填写时省略字段。当前后端未填标题时会从描述提取，成片封面由后端从实际视频提取并永久转存，可能替换暂存封面。客户端不自行截帧或生成成片封面；用户主动选择的暂存封面可上传，最终以任务返回值为准。标题和封面随同原请求保留到幂等重试中。非法输入在提交按钮附近显示提示，避免错误字段滚出屏幕后提示不可见。

列表使用封面网格/大图切换、两行标题、状态标识、作品编号与创建时间；详情顶部显示完整标题，未完成任务展示封面，已完成影片在开始播放前展示封面，点击后才初始化播放器。对话实时视频卡片和历史卡片同步读取这两个字段。封面请求不携带应用 Bearer 令牌；仅接受无内嵌凭据的 HTTP/HTTPS URL。旧记录缺少标题时统一使用 `displayTitle` 的影片编号回退，缺少封面或图片加载失败时提供占位。

详情页提供作品管理入口。编辑页标题最多 35 个 Unicode 码点，只有发生改变的字段才通过 `PATCH /videos/{record_id}` 提交；标题不能清空。更换封面沿用相册上传组件，先调用 `POST /files`，上传成功后用返回的 URL 回显并随 PATCH 保存。生成和封面转存均完成前只允许改标题；历史记录即使显示 `STORED`，如缺少后端封面对象标记仍可能得到 409，页面会提示稍后核对。删除从详情触发，二次确认明确提示不可在 App 中找回；成功后返回并刷新列表。后端仅逻辑删除记录，不取消正在运行的供应商任务，也不清除对象存储文件。删除结果不明时先查详情，不自动重复 DELETE。视频详情和列表以服务端新值为准；旧的结构化聊天消息仍保留发送时的快照。

后端公开任务返回模型名称与可空首尾帧图片地址；未返回完整提示词、时长、画幅、音轨或改写配置，列表/详情不伪造这些字段。历史缺少模型时不推断成某个默认模型。

## 文件上传与素材交互

已核对后端 `docs/File_Upload_API.md`、`src/schema/files.py`、文件路由/服务与运行服务 `/openapi.json`。共用 `FileApi` 使用当前 Bearer 令牌，以 `POST /files`、multipart 字段 `file` 上传；HTTP 201 的统一响应解析为文件编号、URL、文件名、MIME、字节数和上传时间。`GET /files/{file_id}/url` 查询当前用户的文件信息。文件编号与视频记录编号互不混用，创建视频仍传 `first_frame_url`、`last_frame_url`、`cover_url`，不传文件编号。

选择图片后显示本地预览、文件名及上传状态。上传完成才能生成；上传失败保留已选图片，可明确重试、更换或移除，不能带着失败素材继续提交。相册取消不创建上传或视频任务。图片读取和上传期间锁定编辑及生成；切换模型或折叠区域保留素材，重试视频生成复用已上传 URL 和原幂等键。上传没有幂等契约，不自动重试；超时明确告知结果未确认。默认 20 MiB 上限可能被服务端配置进一步限制，413、认证、参数和服务错误有可见提示。

素材、暂存封面复用同一输入组件，地址输入为折叠的备用入口，预览由用户明确触发。暂存封面不受万相的最小尺寸和透明 PNG 限制，成片封面仍由后端提取。公开图片加载不附加应用令牌；客户端不包含模型或对象存储密钥。

`test/core/file_api_test.dart` 覆盖上传、查询、统一响应、错误与重定向；`test/features/video_image_upload_test.dart` 覆盖上传前生成阻止、失败重试、移除、取消、首尾帧约束与小屏大字体。`integration_test/video_upload_test.dart` 和 `test_driver/video_upload_test.dart` 使用安全登录态联调上传、查询、公开读取、万相首尾帧生成和原生播放，结果在 `build/video-upload-verification/`。测试图片由程序构造，不读取私人照片；重复运行通过手机应用支持目录中的测试清单查询既有文件，并使用固定视频幂等键，避免重复消耗。此测试会真实上传并在首次运行生成付费视频，完成后必须恢复正常入口包。清单跨覆盖安装保留；已有固定幂等任务但清单丢失时，必须以 `--dart-define=VIDEO_UPLOAD_FILE_IDS=<原首帧文件编号>,<原尾帧文件编号>` 恢复原素材，不能重新上传后换键生成。

## 语音对话中的视频

首页助手回复支持视频卡片。实时通道读取 `agent.custom` 的 `data.type=video.task`，通过 `response_id` 关联当前助手回复；重复事件更新原卡片，不重复追加消息。文字增量保留视频引用。已取消回复的迟到视频事件被忽略，缺失、未知或非法扩展数据不影响普通语音聊天。

聊天历史读取 `response_metadata.video`，恢复对话和按日查询聊天记录均展示同一张视频卡片；旧记录没有该字段时继续展示原文字。不从自然语言或普通 URL 猜测视频完成状态，不硬编码七牛域名。

`VideoReference` 统一维护任务编号、生成/转存状态和 URL 校验，完整视频任务继承同一套状态判断。只有 `SUCCEEDED + STORED + 有效 HTTP(S) 七牛地址` 展示“播放视频”；其余状态提供“查看进度”，完成但缺少有效链接时提示刷新详情。完整地址在播放页可展开查看、选择或复制，不向播放器发送应用 Bearer 令牌。

卡片默认不创建播放器。点击播放后暂停本地唤醒、结束当前音频采集和播报，再打开独立播放页；用户点击动作后自动开始视频。关闭播放页时等待路由退出和原生播放器释放完成，再用原助手、音色和线程新建语音连接，不重发查询或生成请求。应用在后台、账号配置已变更或播放器释放失败时不自动恢复麦克风。未连接语音时返回聊天仅恢复默认唤醒。

播放器提取到 `video_playback.dart`，对话播放和原视频详情共用加载、重试、进度、生命周期与资源释放逻辑。复用 `openConversationVideo` 的历史记录页已在上层暂停唤醒，无需建立语音连接。
