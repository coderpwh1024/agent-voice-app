# 视频工作室

独立模块位于 `lib/features/videos/`：`data/` 维护请求与契约，`video_studio_page.dart` 维护作品列表，`video_create_page.dart` 维护生成表单，`video_detail_page.dart` 维护查询、轮询和播放器，`video_widgets.dart` 维护视觉组件。复用现有 `AgentApiClient` 的 Bearer 认证和统一响应解析；不持有模型或七牛密钥。

## 入口与设计

首页右上角的影片图标进入视频工作室；“记忆与对话”也提供同一入口。打开工作室时暂停本地唤醒，返回首页后恢复。正在语音通话时禁用入口，避免影片播放与语音采集冲突。

视频工作室采用 Instagram 风格的杂志排版：暖白底色、墨黑文字、细分隔线、少量低饱和橄榄色，作品封面承担主要视觉。入口名称仍为“视频工作室”，页头使用“映像 / STUDIO”字标与小号中文说明，固定标题使用本地打包的宋体，正文和用户影片标题沿用系统无衬线字体。

设计参考：

- [Instagram 官方品牌设计说明](https://www.meta.com/design-at-meta/blog/the-new-instagram-brand-identity/)：克制的界面、更多呼吸空间，让内容成为主角。
- [Kinfolk](https://www.kinfolk.com/)：摄影优先、清晰层级与杂志式留白。
- [摄影档案移动端案例](https://www.behance.net/gallery/201812475/Portfolio-website-for-photographer-Web-Design)：简洁作品网格与细节信息的组织。

首页取消促销式插画大卡，使用字标、编辑式标题和主创作按钮，作品区提供双列 4:5 封面网格及单列 16:9 大图列表切换；切换仅改变布局，不重新请求或丢失分页数据。小屏或大字体自动使用单列。封面比例只影响预览裁剪，不改变原影片比例。空封面与加载失败提供中性占位，失败分页提示放在加载入口附近。

创建页采用统一的三段编辑区与细边输入框；详情以标题和影片为主，创作进程可展开查看。对话视频卡片和独立播放器同步采用同套圆角、配色与字级。主题已提取到 `lib/core/theme/`，视频、语音、个人主页、对话与记忆共用同一套配色和控件。支持深色模式、安全区域及系统大字体。宋体为 SIL OFL 1.1 授权 Noto Serif SC 的静态子集，授权与来源位于 `assets/fonts/`，约 218 KB，不需要联网加载字体。

## 接口

已核对相邻后端仓库 `docs/Video_API.md`、视频 schema、路由、服务与运行中的 `/openapi.json`。整体后端还包括邮箱认证、用户资料、语音会话、聊天调用/流式/历史/归档、长期记忆、邮件技能及 AG-UI；新增模块沿用现有认证和服务地址。

| 操作 | 接口与行为 |
| --- | --- |
| 生成 | `POST /videos`，带 `Idempotency-Key`，解析 HTTP 202 中的统一响应 |
| 列表 | `GET /videos?page=1&page_size=20`，按需传 `status`、`storage_status` |
| 详情 | `GET /videos/{record_id}`，可从列表进入或按编号查询 |

身份由当前 Bearer 令牌绑定，不向视频接口发送 `user_id`。列表显示后端真实 `total`，按后端页码加载，去除并发变化可能带来的重复 ID。筛选包括全部、已完成（生成成功且已转存）、生成中、排队中、生成失败；其他状态仍可在“全部”与详情查看。分页失败保留已加载作品，刷新失败可重试原刷新。

表单支持两个 HappyHorse 模型、全部九种比例、480P/720P/1080P、3–15 秒、水印与可选随机种子。1.0 模型不会发送 480P。按 Unicode 码点验证最多 5000 字符及最多 2500 个中日韩统一表意文字，种子范围 0–2147483647。

同一次提交在重试时使用原幂等键和参数；请求中禁用重复点击和返回。返回未知结果时锁定参数，并允许核对原提交。在当前工作室中重新打开表单仍保留该次待确认提交。此状态只保存在内存；退出工作室或重启 App 后，应先在作品列表核实已提交任务，避免主动新建重复需求。后端返回 `SUBMISSION_UNKNOWN` 时详情明确要求核实，不自动重新生成。

详情页仅在前台每 10 秒查询尚未完成的任务，最多连续自动查询 60 次；切后台暂停，回前台重新核对。查询失败停止自动请求并提供手动刷新。已完成、失败、取消、失效、提交待核实分别展示；生成成功但转存失败保留成功事实并提示后台会重试，不展示虚假的进度百分比。

只有 `status=SUCCEEDED`、`storage_status=STORED` 且七牛 URL 为有效 HTTP(S) 链接时才加载播放器与提供复制链接。阿里云临时签名链接不展示、不复制。播放器使用 Flutter 官方 `video_player`，支持播放、暂停、拖动进度、缓冲和失败重试；离开 App 时暂停，页面销毁时释放资源，不自动开始播放。

后端公开任务包含可空的 `title` 和 `cover_url`，生成响应、列表、详情统一解析。创建页提供可选标题（最多 200 个 Unicode 码点）、可选 HTTP/HTTPS 暂存封面 URL（最多 2048 字符）和独立手动预览；首尾空白会去除，未填写时省略字段。当前后端未填标题时会从描述提取，成片封面由后端从实际视频提取并永久转存，可能替换暂存封面。客户端不自行截帧、生成或上传封面，以任务返回值为准。标题和封面随同原请求保留到幂等重试中。非法输入在提交按钮附近显示提示，避免错误字段滚出屏幕后提示不可见。

列表使用封面网格/大图切换、两行标题、状态标识、作品编号与创建时间；详情顶部显示完整标题，未完成任务展示封面，已完成影片在开始播放前展示封面，点击后才初始化播放器。对话实时视频卡片和历史卡片同步读取这两个字段。封面请求不携带应用 Bearer 令牌；仅接受无内嵌凭据的 HTTP/HTTPS URL。旧记录缺少标题时统一使用 `displayTitle` 的影片编号回退，缺少封面或图片加载失败时提供占位。

后端公开任务结构不包含提示词、时长、画幅与模型参数，列表/详情不伪造这些字段。

## 验证与真机安装

```sh
flutter analyze
flutter test
./scripts/install_usb_debug.sh 20b2a515
```

脚本构建正常入口 Debug APK、递增手机已安装的构建号、覆盖安装并启动应用。服务地址为 `http://127.0.0.1:8000`，通过 `adb reverse tcp:8000 tcp:8000` 访问电脑本地后端；不是 Android 模拟器专用的 `10.0.2.2`。USB 重连后应重新执行脚本或建立反向映射。

真机联调使用手机已有安全登录态，不导出令牌。它验证资料、语音能力、聊天记录、长期记忆，以及视频创建、重复幂等提交、列表、查询、实际生成、转存、下载和原生播放，并输出页面截图。会生成一条真实 3 秒 480P 测试影片并消耗服务端额度；同一测试键可重复执行而不新增影片。运行前需要已登录且后端启用视频模块：

```sh
flutter build apk --debug --build-number=<高于手机当前版本> \
  --target=integration_test/video_backend_test.dart \
  --dart-define=API_BASE_URL=http://127.0.0.1:8000
# 将生成的测试 APK 复制到单独路径后运行；避免与最终正常入口 APK 混淆。
flutter drive -d 20b2a515 --keep-app-running \
  --driver=test_driver/video_backend_test.dart \
  --target=integration_test/video_backend_test.dart \
  --use-application-binary=<测试APK路径>
./scripts/install_usb_debug.sh 20b2a515
```

结果与截图位于 `build/video-verification/`，不会提交登录凭据。联调测试明确断言生成与保存成功，服务未启用或上游失败时不会误报通过。若返回 `503 视频生成功能未启用`，需要在本地 Nacos 的应用 YAML 中设置 `video.enabled: true` 后重启；开关在启动时读取。

注意：Flutter 3.47 的 `flutter drive` 默认会在结束时卸载测试应用。复用正常应用包名和已有登录态时必须传 `--keep-app-running`；测试完成后用安装脚本覆盖恢复正常入口，避免卸载导致本地登录态丢失。

## 语音对话中的视频

首页助手回复支持视频卡片。实时通道读取 `agent.custom` 的 `data.type=video.task`，通过 `response_id` 关联当前助手回复；重复事件更新原卡片，不重复追加消息。文字增量保留视频引用。已取消回复的迟到视频事件被忽略，缺失、未知或非法扩展数据不影响普通语音聊天。

聊天历史读取 `response_metadata.video`，恢复对话和按日查询聊天记录均展示同一张视频卡片；旧记录没有该字段时继续展示原文字。不从自然语言或普通 URL 猜测视频完成状态，不硬编码七牛域名。

`VideoReference` 统一维护任务编号、生成/转存状态和 URL 校验，完整视频任务继承同一套状态判断。只有 `SUCCEEDED + STORED + 有效 HTTP(S) 七牛地址` 展示“播放视频”；其余状态提供“查看进度”，完成但缺少有效链接时提示刷新详情。完整地址在播放页可展开查看、选择或复制，不向播放器发送应用 Bearer 令牌。

卡片默认不创建播放器。点击播放后暂停本地唤醒、结束当前音频采集和播报，再打开独立播放页；用户点击动作后自动开始视频。关闭播放页时等待路由退出和原生播放器释放完成，再用原助手、音色和线程新建语音连接，不重发查询或生成请求。应用在后台、账号配置已变更或播放器释放失败时不自动恢复麦克风。未连接语音时返回聊天仅恢复默认唤醒。

播放器提取到 `video_playback.dart`，对话播放和原视频详情共用加载、重试、进度、生命周期与资源释放逻辑。复用 `openConversationVideo` 的历史记录页已在上层暂停唤醒，无需建立语音连接。

新增测试覆盖结构化事件与流式文字、重放去重、乱序结果、取消后迟到事件、无视频字段的旧消息、非法链接、历史卡片、小屏/大字体及音频交接。真机集成测试 `integration_test/voice_video_test.dart` 通过语音 WebSocket 发送文字查询已有测试影片（不重复生成），验证真实 `video.task`、七牛播放、播放期间断开收音以及返回同一线程。配套驱动为 `test_driver/voice_video_test.dart`，截图和结果输出到 `build/voice-video-verification/`。
